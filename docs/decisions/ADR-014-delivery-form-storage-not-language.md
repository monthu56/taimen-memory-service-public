# ADR-014: Форму поставки определяет хранилище, а не язык; «один файл» уже достижим без смены языка

## Status

Proposed (2026-07-27). Закрывает вопрос, поднятый в
[ADR-011](ADR-011-on-prem-delivery-and-artifact-licence.md) и оставленный там открытым
как «эксплуатационный мотив, требующий измерения».

## Context

ADR-011 отверг переписывание на Rust ради секретности, но оставил живым эксплуатационный
мотив — размер артефакта, RSS, поставка одним файлом — и потребовал **измерить** его,
прежде чем на нём что-то строить. ADR-012 зафиксировал, что владелец принял зависимость
от инфраструктуры (PostgreSQL + AGE + pgvector отдельным компонентом) как данность.

Измерения проведены.

### 1. «Один исполняемый файл» получен уже сегодня, без смены языка

PyInstaller 6.21.0 собрал текущий сервис в один файл **48,5 МиБ за 22 секунды**. Файл
запущен в контейнере `debian:12-slim`, где Python физически не установлен, против настоящей
БД с AGE 1.6.0 и pgvector 0.8.0, и отработал весь контракт: `/healthz`,
`/api/brain/retain|search|stats`, `/console`, `/demo`, `/openapi.json` — всё 200, ответы
побайтово те же, что у `platform-memory-serve`. Правок продуктового кода — ноль, только
четыре флага сборки. Сломалось ровно одно место: jinja-шаблоны консоли не попали в артефакт,
лечится флагом `--collect-data platform_memory`.

### 2. Двухкомпонентность не убирается ни одним языком

`age.so` (2,98 МБ) и `vector.so` (1,10 МБ) — **backend-расширения PostgreSQL**: у них нет
клиентского ABI, они зовут внутренний C-API сервера (fmgr, SPI, каталоги, хуки) и собраны
через PGXS против заголовков конкретного мажора. Слинковать их в клиентский бинарь нельзя
ни в Rust, ни в C++, ни на чём.

Арифметика добивает: `memory-db` = 645 МБ, `memory-service` = 326 МБ. Бинарь **нулевого**
размера убирает треть контура — причём более лёгкую и более простую треть: половина-БД
это 53 авторские строки поверх стокового образа `apache/age`.

### 3. Отраслевая норма

Проверено 16 вендоров класса «движок + хранилище + HTTP API». **Ни один** не документирует
одиночный бинарь как рекомендуемый способ on-prem-установки. Weaviate — это один Go-бинарь
с нулевыми рантайм-зависимостями, но в документации по развёртыванию его нет; Qdrant
публикует бинари, но в документации пишет «скомпилируй из исходников». Все, кто **может**
отдать один файл, отдают контейнер. Те, у кого «один файл со встроенной БД» есть, сами
пишут: для продакшена подключай внешнюю СУБД. А там, где есть и БД, и рантайм, «один файл»
решается **omnibus-пакетом** (.deb/.rpm), и язык при этом может быть интерпретируемым —
GitLab написан на Ruby.

**Один файл — свойство архитектуры хранения, а не языка компиляции.**

### 4. Rust против C++ — предметно, а не «безопасность памяти вообще»

| Пункт | Итог |
|---|---|
| Клиент PostgreSQL | **Rust.** Эталон на C++ собран статикой под musl (6,25 МБ), но **не самодостаточен**: из `FROM scratch` libpq требует `/etc/passwd`, статический OpenSSL всё равно ищет CA-бандл файлом. `pkg-config --static --libs libpq` выдал нерабочую link line. `tokio-postgres` — чистая Rust-реализация wire-протокола: libpq не нужен, корни вкомпилированы. C++ даёт «один файл плюс требования к окружению», Rust даёт один файл (4,99 МБ, 2,63 с LTO, RSS 1,4 МиБ) |
| Асинхронность | **Паритет.** У libpqxx настоящей async-модели нет, но все 20 маршрутов сервиса синхронные `def`, соединение живёт один запрос — модель переносится один-в-один на thread-per-request |
| AGE/agtype | **Паритет.** Драйверов нет ни для одного из двух; писать самим — но здесь это ~50 строк, потому что код возвращает `properties(n)`, а не вершину |
| pgvector | **Паритет.** `pgvector-cpp` (MIT) и `pgvector-rust` (Apache-2.0) — обе в организации самого pgvector. Утверждение «в C++ нет помощников pgvector» неверно |
| HTTP-сервер | **Rust**, но по конкретной причине: из пяти C++-кандидатов двое мертвы (oatpp, Pistache — релизы 2024 года), а у самого живого, `cpp-httplib`, за полтора года шесть CVE, включая CVSS 9.9 (инъекция CRLF) и подмену `REMOTE_ADDR` клиентом — последняя ломает ровно ту логику, на которой держится rate-limit витрины |
| MCP | **Никто.** SDK для C++ не существует; у Rust — Tier 2 с третьим ломающим мажором за год. Практический вывод для обоих: оставить MCP на Python отдельным сайдкаром (437 строк, 5 % кода, opt-in) |
| Безопасность | **Rust.** Python-стек тоже не стерилен (Starlette CVE-2026-48710, CVE-2026-54283 — обе закрыты в зафиксированных `uv.lock` версиях). Но разница в классе: в C++ к логическим багам добавляется повреждение памяти, то есть RCE на сервере с данными заказчика; и в доставке исправления — здесь `uv lock --upgrade`, там перевыпуск статического артефакта у каждого заказчика |

Объём порта на C++: 8609 строк + 3474 строки тестов при коэффициенте 2,5–3,5x — это
22–30 тыс. строк, плюс написать самим протокол MCP, OpenAI-клиент с ретраями,
Louvain/Leiden под пермиссивной лицензией, OpenAPI-спеку руками и формат 422 от pydantic.

## Decision

1. **Не переписывать сервис ни на C++, ни на Rust ради формы поставки.** Мотив измерен
   и не подтвердился: бинарь убирает треть веса контура и не убирает ни одного компонента.
2. **Если требование «один исполняемый файл» остаётся жёстким — закрывать его сборкой,
   а не переписыванием.** PyInstaller/Nuitka дают артефакт за дни. Это форма поставки,
   и только она: секретности не даёт (см. ADR-011), двухкомпонентности не отменяет.
3. **Настоящий рычаг — хранилище.** Единственная архитектура, где «один файл» становится
   честным, — отказ от AGE и pgvector в пользу встраиваемого движка. Это отдельное решение
   с собственной ценой (см. Alternatives), и принимать его нужно **сейчас или никогда**:
   владелец снял требование совместимости со старыми базами (ADR-013), то есть окно
   бесплатной смены хранилища открыто до первой платящей инсталляции.
4. **Дешёвые меры, не требующие ни смены языка, ни смены хранилища:** `numpy` (39 МБ + 27 МБ
   библиотек) используется ровно в одном файле — `ingest/_minhash.py`, 111 строк, и только
   ради арифметики `uint64` и генератора перестановок. Вместе с попутными зависимостями это
   заметная доля веса образа. Требует замера и отдельной задачи.

## Consequences

- Вопрос «на каком языке» закрыт по всем трём мотивам: латентность (ADR-010), секретность
  (ADR-011), форма поставки (настоящий ADR). Остаётся четвёртый, не рассмотренный:
  удовольствие от разработки. Он законен, но его нельзя выдавать за инженерный.
- Экономия RSS реальна и не оспаривается: 128–158 МБ против 1,4–30 МиБ. Для SMB-продукта
  с многими инсталляциями это может значить деньги — но считать надо после того, как
  определена архитектура хранения, иначе считается не то.
- Признаётся расхождение: постановка «поставка одним бинарём» противоречила ADR-012, где
  зависимость от инфраструктуры уже принята владельцем как данность. Расхождение снято
  измерением, а не спором.

## Alternatives

- **Встраиваемое хранилище вместо PostgreSQL — единственный путь к честному «одному файлу».**
  Кандидат: **LadybugDB** (MIT, форк Kuzu после его архивации Apple 2025-10-10; 1496 звёзд,
  79 контрибьюторов, v0.18.3 от 2026-07-21, релизы каждые 1–2 недели). Закрывает **все три**
  куска хранилища одной библиотекой: openCypher (31 запрос из `graph/store.py` мигрирует
  по диалекту, а не переписывается в код), встроенный дисковый HNSW вместо pgvector,
  встроенный FTS на Snowball со стеммером `russian` и BM25 вместо `to_tsvector('russian')`.
  Плюс Louvain и PageRank из коробки. Публикуются готовые статические библиотеки
  (linux x86_64 — 25,3 МБ), итоговый бинарь реалистично 40–70 МБ против образа 443 МБ.

  **Цена, которую надо назвать честно:** (1) переход от схемной свободы AGE к обязательной
  схеме — Ladybug требует `CREATE NODE TABLE` с типизированными колонками и первичным ключом,
  а сервис кладёт произвольный frontmatter в свободную карту `props` и создаёт типы узлов
  на лету при первом `MERGE`; (2) радиус поражения меняется — сегодня падение БД это
  перезапуск Postgres и 500 от сервиса, после встраивания segfault в библиотеке убивает
  процесс сервиса целиком, а crash-класс баги Ladybug за последний квартал сидят ровно
  в FTS и векторном индексе; (3) неснятый вопрос: у Kuzu FTS-индекс был **иммутабелен**
  (при вставке требовалось пересоздание), а `/api/brain/retain` пишет факты на лету
  и ожидает, что они сразу находятся — в документации Ladybug мутабельность не зафиксирована.
  Требует спайка **до** решения.
- **CozoDB** — вычеркнут: последний коммит 2024-12-04, проект спит ~20 месяцев.
- **SurrealDB embedded** — вычеркнут по лицензии: BSL 1.1 с переходом в Apache-2.0 только
  01.01.2030 и запретом на «Database Service». Линковка ломает инвариант обратимости.
- **PGlite** (встроенный Postgres в процессе, AGE и pgvector формально есть) — отложен:
  обёртка AGE в версии 0.0.5, режим single-user, нативный хост — проект на 93 звезды.
- **Запуск `postmaster` дочерним процессом из бинаря** — работает, но это
  самораспаковывающийся архив на 60–100 МБ и роль упаковщика PostgreSQL впридачу.
- **ANN-индекс при переходе на встраиваемое хранилище не нужен на текущем масштабе:**
  1661 чанк × 1536 float32 = 10 МБ, полный перебор — доли миллисекунды. Индекс становится
  нужен от 10^5–10^6 чанков.

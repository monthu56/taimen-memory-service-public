# ADR-012: Новый уникальный код пишется сразу под компиляцию и защиту

## Status

Proposed (2026-07-27; по прямому решению владельца после разбора мотивов Rust —
см. [ADR-010](ADR-010-graph-latency-jit-not-rust.md) и
[ADR-011](ADR-011-on-prem-delivery-and-artifact-licence.md)).

## Context

ADR-011 показал, что защищать **существующий** код бессмысленно: 24.7 % строк вендорены из
публичного MIT-репозитория, RRF — учебный алгоритм на 27 строк, промпты уходят открытым текстом
на внешний шлюз каждым запросом, а онтология вообще живёт не в коде, а в БД. Ретроактивная защита
коммодити — отрицательная величина.

Но из этого **не следует**, что защита не нужна никогда. Владелец сформулировал позицию точно:

> «У нас вроде бы нет уникального кода, пока что. Но уникальный код мы будем писать сразу
> под компиляцию и максимальную защиту.»

Это правильная асимметрия. Ретрофит защиты дорог — именно поэтому ADR-011 отверг переписывание.
Закладывать защиту в момент написания нового модуля стоит несопоставимо дешевле: граница
проводится один раз, на чистом листе, до того как код обрастёт вызовами из десятка мест.

Владелец также зафиксировал требования к поставке и модель угроз:

- **Противник по сети:** чужие из интернета и **соседние сервисы в сети заказчика** (боковое
  движение). Сам заказчик из модели угроз выведен — на его железе это недостижимо (ADR-011).
- **Универсальность:** один артефакт на всех заказчиков; любая ОС и архитектура; **закрытый
  контур без интернета**.
- Зависимость от инфраструктуры (PostgreSQL + AGE + pgvector отдельным компонентом) принята
  как данность: мечта об «одном бинаре, который запускает вообще всё» снята самим владельцем.

## Decision

### 1. Критерий: что считается «уникальным кодом»

Модуль подлежит режиму защиты, если выполняется **хотя бы одно**:

- содержит параметры, выведенные из данных (веса ранжирования, пороги, обученная модель);
- реализует эвристику, которую нельзя восстановить из наблюдения за поведением API;
- воплощает предметную экспертизу, купленную опытом, а не взятую из статьи.

И **ни одно** из исключающих:

- алгоритм назван в публичной документации или ADR (тогда он уже раскрыт);
- код вендорен из внешнего репозитория (лицензия следует за производным произведением);
- содержимое уходит третьей стороне при работе (промпты — на LLM-шлюз, Cypher — в лог БД).

Последнее исключение важно и на практике режет больше всего: **прятать в компилируемый модуль
то, что сервис сам отправляет наружу открытым текстом, — самообман.** Если промпт или запрос
покидает процесс, его защита решается не компиляцией, а тем, чтобы он не покидал процесс.

### 2. Форма: отдельный компилируемый модуль за стабильным интерфейсом

Новый уникальный код оформляется **не** как правка существующих файлов, а как отдельный
компилируемый модуль, подключаемый к сервису через узкий Python-интерфейс (расширение
CPython). Питоновский пакет вызывает его через явную границу и **сохраняет работающий
fallback** на открытой реализации.

Три следствия, ради которых выбрана именно эта форма:

- **Инвариант обратимости не нарушается.** Проприетарный модуль живёт **вне** границы
  Apache-2.0-пакета, отдельным репозиторием и с собственной лицензией. Открытый пакет остаётся
  вырезаемым в open-source вместе с fallback'ом — просто без коммерческого модуля.
- **Контракт `/api/brain/*` не затрагивается.** Граница проходит внутри движка, снаружи схемы
  ответов те же. Расширение — только аддитивное.
- **Переписывать сервис не нужно.** Модуль подключается к нынешнему Python без порта 8585 строк.

Язык модуля — Rust (PyO3 + maturin) либо C++ (pybind11). **Выбор пока открыт**: сравнительный
дью-дилидженс под этот стек запущен, решение фиксируется дополнением к этому ADR. Предварительно
Rust выглядит предпочтительнее для соло-фаундера — воспроизводимая кросс-сборка колёс под
manylinux x86_64/aarch64 через maturin дешевле, чем CMake + manylinux вручную, а модуль будет
разбирать недоверенный вход. Но это не решено, и «интересно писать» — законный критерий,
когда цена сопоставима.

### 3. Правила, действующие с момента принятия

1. Новый модуль, попадающий под критерий (1), сразу заводится в отдельном репозитории
   с проприетарной лицензией — **не** в этом дереве.
2. В открытом пакете остаётся интерфейс и работающая (пусть более слабая) реализация по
   умолчанию. Отсутствие проприетарного модуля не ломает сервис.
3. Секреты, промпты и запросы к БД внутрь защищаемого модуля не прячутся — см. исключение
   в критерии (1).
4. Требование «один артефакт на всех заказчиков» соблюдается: модуль одинаков везде,
   различия — только в конфиге и лицензионном ключе.
5. Требование «любая ОС и архитектура» становится реальной ценой этого решения: каждое
   компилируемое колесо надо собирать и тестировать под каждую целевую платформу. Это первое,
   что подорожает; закладывать в оценку любой задачи с таким модулем.

### 4. Что этим ADR **не** решается

Требование **закрытого контура без интернета** этим решением не закрывается и является
**более крупной продуктовой проблемой, чем защита кода**. Сегодня без интернета сервис
теряет обе интеллектуальные функции: `CB_EMBEDDING_PROVIDER=fake` даёт хэш-эмбеддинги
(`index/embeddings.py` — токены через `hashlib`, семантики нет), а `CB_LLM_PROVIDER=echo`
возвращает контекст без вызова модели (`retrieval/llm.py:23`). Это заглушки для тестов,
а не офлайн-режим. Полноценный закрытый контур требует локальной модели эмбеддингов и
локальной LLM — отдельное решение, отдельный ADR, и по влиянию на продукт оно больше,
чем всё, что обсуждалось в ADR-010…012.

## Consequences

- Появляется постоянная граница «открытое ядро / проприетарный модуль», которую надо
  поддерживать: два репозитория, две лицензии, матрица сборки колёс, синхронизация версий.
  Это плата, и она начисляется с первого же модуля, а не с десятого.
- Сборка перестаёт быть однокомандной: сегодня `uv sync` — всё. Появится этап компиляции
  и кросс-сборки, а с ним CI под несколько платформ.
- Тесты открытого пакета обязаны проходить **без** проприетарного модуля (fallback), иначе
  инвариант обратимости деградирует молча. Это требование к каждому такому модулю.
- Отладка усложняется: стектрейс из скомпилированного модуля не покажет строку исходника.
- Защита остаётся **частичной и честно ограниченной**: строковые константы достаются из
  `.rodata`, поток управления восстанавливается реверс-инженером. Цель формулируется как
  «поднять цену копирования», а не «сделать копирование невозможным» — второе недостижимо,
  и владелец это признаёт.

## Alternatives

- **Защищать всё, включая существующий код.** Отвергнуто в ADR-011: 80–150 человеко-дней
  ради активов, которых нет внутри артефакта.
- **Не защищать ничего, полагаться на темп и данные.** Разумная позиция для сегодняшнего
  состава кода — и, по сути, действующая. Настоящий ADR её не отменяет, а ограничивает
  во времени: она перестаёт действовать в момент появления первого модуля по критерию (1).
- **Обфускация Python (PyArmor) для новых модулей вместо компиляции.** Дешевле на старте
  ($52 и дни вместо недель), но защита слабее и, главное, не даёт побочных выгод
  компилируемого модуля. Остаётся запасным вариантом, если стоимость матрицы сборки
  окажется выше ожидаемой.
- **Писать уникальный код на Python и компилировать потом.** Ровно тот ретрофит, дороговизну
  которого установил ADR-011. Отвергнуто — это и есть мотив настоящего ADR.
